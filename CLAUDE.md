# ghostrules — project memory for Claude Code

## What this project is
`ghostrules` is a Python CLI + GitHub Action that scans a repository (and optionally the user's
machine) for **hidden instructions and risky configuration in the files AI coding agents read and
obey**: `AGENTS.md`, `CLAUDE.md`, `.cursorrules`, Copilot instructions, skills, MCP configs, etc.

Tagline: *"Find the instructions your AI agent sees but you don't."*

It is a **defensive** security tool. It only reads files and reports findings. It never executes
anything it finds, never makes network requests, and never phones home.

## Source-of-truth documents (read before coding)
- `docs/SPEC.md` — features, CLI, file targets, output formats, config. **The contract.**
- `docs/RULES.md` — every detection rule: ID, severity, logic, true/false positive examples.
- `docs/PLAN.md` — build order, phase by phase, with acceptance criteria.

If something in the code disagrees with these docs, the docs win unless the user says otherwise.
If a doc is ambiguous, pick the simplest reasonable option and note it in `docs/DECISIONS.md`.

## Tech stack
- Python **3.10+**, packaged with `pyproject.toml` (hatchling), src layout: `src/ghostrules/`.
- CLI: **typer**; terminal output: **rich**. TOML config: `tomllib` (3.11+) / `tomli` fallback.
- No other runtime dependencies unless clearly justified. **No network libraries at runtime.**
- Dev: `pytest`, `pytest-cov`, `ruff` (lint + format), `mypy` (lenient is fine).

## Commands
```bash
pip install -e ".[dev]"          # install for development
pytest -q                        # run tests
ruff check . && ruff format .    # lint + format
ghostrules scan examples/poisoned-repo   # manual smoke test (must find issues)
ghostrules scan examples/clean-repo      # must report zero findings
```

## Code conventions
- Each rule is a small class/function in `src/ghostrules/rules/` registered in one registry.
  Rules receive a parsed `ScanTarget` (path, kind, text, lines, parsed JSON/TOML if any) and
  yield `Finding` objects. Rules must be pure: no I/O, no global state.
- `Finding` fields: `rule_id, severity, title, message, path, line, column, end_column, snippet,
  decoded (optional str), fix_hint`.
- Severities: `critical > high > medium > low > info`.
- Snippets must render invisible characters visibly, e.g. `⟦U+200B ZERO WIDTH SPACE⟧`.
- **Secrets must always be masked** in every output format (`ghp_****…a1b2`).
- Type hints everywhere; small functions; docstrings on public functions.
- Every rule needs at least one positive and one negative test.

## Safety rules for this repo (important)
- Test fixtures and demo files must be **defanged**: use `attacker.example`, `example.com`,
  `exfil.example`, fake tokens like `ghp_EXAMPLEEXAMPLEEXAMPLEEXAMPLE0000` — never real
  domains, real webhooks or working payloads.
- Fixtures containing invisible characters are **generated by `scripts/make_fixtures.py`**,
  not hand-typed, so they are reproducible and reviewable.
- Never add code that executes, downloads or evaluates scanned content.

## Workflow
- Work phase by phase following `docs/PLAN.md`. After each phase: run tests + ruff, then
  stop and summarize what was done and what is next.
- Commit after each phase with a conventional commit message (`feat:`, `test:`, `docs:`…).
- Keep the README in English and keep it updated when CLI flags change.
