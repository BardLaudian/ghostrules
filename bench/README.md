# Benchmark

Two measurements, both reported with their misses and without tuning on them (W6 of
[docs/design/v0.4/REMEDIATION.md](../docs/design/v0.4/REMEDIATION.md)). The latest numbers are in
[RESULTS.md](RESULTS.md), generated by `python bench/run.py report --write`.

## Recall: the attack set (`attacks/`)

<!-- bench:cases:start -->110 cases (37 by the author, 4 from the independent review, 69 from public sources), each a technique written from a public description<!-- bench:cases:end --> (sources in `attacks/sources.toml`:
Rehberger and Butler on Unicode smuggling, Trojan Source, Pillar's Rules File Backdoor, Invariant
Labs on MCP tool poisoning, Check Point's Claude Code CVEs, OWASP's malicious-skills entry), with
the rule that should catch it and whether it does today (`status = "detected"` or `"known-miss"`).

- **Defanged.** Hosts are `.example` (plus one public collector service used with an all-zero id),
  tokens have the `EXAMPLE` shape, and a test checks every URL. No payload is copied from a source.
- **No invisible characters in the files.** `{tags:TEXT}`, `{vs:TEXT}`, `{u+200B}`, `{b64:TEXT}` and
  `{hex:TEXT}` are expanded when a case runs (`lib.py`), so the committed files are reviewable.
- **Two ways to count a hit.** *Reported*: an expected rule fired at the default settings (shown
  findings). *Fails the default check*: it fired at `high` or `critical`, which is what
  `--fail-on high` stops. They differ on purpose: visible prose is `low` by default.
- **Misses stay in the base and are listed.** A test fails when a declared status stops matching what
  the scanner does, so a miss that gets fixed must be updated, and a detection that regresses shows.
- **Provenance.** `origin` is `public` (a public technique), `review` (a case from the independent
  review) or `author` (written by the maintainer, who knew what the rules match: not independent). <!-- bench:provenance:start -->Only **4 of the review's 18 cases**<!-- bench:provenance:end --> are included:
  the ones `REMEDIATION.md` describes. The other 14 are not in the repository and are not
  invented here; add them as `origin = "review"` cases when the list is available. Ideally someone
  who has not seen the rules writes another 20.

## Precision: the held-out set (`heldout.toml`)

100 repositories frozen on 2026-10-29 before any v0.4 tuning (selection in the file header). They are
scanned by `python bench/run.py heldout` with the default settings and an empty configuration; the
findings stay in `bench/.cache` (ignored by git) and only counts and fingerprints are committed
(`heldout-results.json`). Each finding is labelled in `heldout-labels.toml` as `tp`,
`benign-context` or `fp`; **precision for a user = tp / (tp + benign-context + fp)**, because a
right pattern in a harmless place is still something someone has to read.

- **The labels are provisional.** They were given by the assistant that ran the benchmark, from the
  finding and the lines around it, and no human has reviewed them. Borderline calls are noted in
  [RESULTS.md](RESULTS.md). Each label records who gave it (`labeler` in `heldout-labels.toml`).
  `python bench/run.py review-sheet` writes `labels-review.csv` (repository, rule, `file:line`,
  three lines of context, an empty `human_label`; the assistant's label is left out so the review
  is blind). A person fills `human_label` with `tp`, `benign-context` or `fp`; those labels win over
  the assistant's and the report then gives the human-reviewed and the assistant-only figures
  separately, never as one number. All 21 findings have a human label today; one person labelled them, so there is no second opinion.
- **Every percentage carries its sample size and a 95 % Wilson interval** (`lib.share`).
- **The set is small.** <!-- bench:heldout:start -->100 repositories gave 21 findings<!-- bench:heldout:end -->: a per-rule percentage on 1 to 6 findings
  is an anecdote, not an estimate.
- **Never tune on it.** A rule changed after reading these findings would no longer be measured by
  this set. Fixing what it shows needs a new held-out set, frozen first.

### Precision

<!-- bench:precision-detail:start -->
**Precision: 100 repositories** frozen before any v0.4 tuning (851 agent files, default settings). They gave 21 findings, and 2 repositories would fail the default check. Precision for a user is true positives over everything reported, because a right pattern in a harmless place is still something to read: **4 of 21 (19 %, 95 % CI 8–40 %)** (0 findings unlabelled). All 21 labels were given by a human reviewer (the assistant's earlier labels were replaced where they differed). Per rule: GR014 1 of 5; GR022 1 of 6; GR102 1 of 1; GR107 1 of 1; GR003 0 of 2; GR011 0 of 1; GR012 0 of 4; GR110 0 of 1. 21 findings are too few for a percentage per rule to mean much.
