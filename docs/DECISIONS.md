# Decisions

Choices made where `SPEC.md`, `RULES.md` or `PLAN.md` were ambiguous or inconsistent.
Newest at the bottom of each section. "Phase N" says when the decision takes effect.

## Applied (Phases 0-1)

- **Git:** the project directory was not a repository; `git init -b main` was run in Phase 0 so
  per-phase commits are possible.
- **Single version source:** `__version__` in `src/ghostrules/__init__.py`, read by hatch.
- **Rule registry:** `rules/registry.py` holds `Rule` + `@rule`; `rules/__init__.py` re-exports it
  and imports the rule modules. `Rule.scans_decoded` marks GR010-GR016.
- **Hidden-text pass:** text decoded by a rule (`Finding.decoded`) is scanned as a virtual
  `instructions` target by `scans_decoded` rules only (no recursion). Results are attributed to
  the parent's location and get +1 severity (cap critical).
- **Suppression scope:** inline `ghostrules-ignore` never suppresses GR001/GR002 (SPEC §6), and
  also cannot suppress findings derived from decoded hidden text. `ScanResult.suppressed` counts
  suppressed findings so reports can show it.
- **Size/binary limits:** the 2 MB / binary skip only applies to unrecognised files added by
  `--all-files`. Known target files are always scanned, otherwise padding a file would hide it.
- **Symlinks:** never followed during repo discovery (no escaping the root, no loops). `--home`
  accepts symlinked dotfiles.
- **Explicit file argument:** `scan some/file` scans it even if it is not a known target
  (`kind = other`, unless its name matches a target glob).
- **Reported paths:** relative to the scan root; with several roots, prefixed by the root as given;
  home files are labelled `~/...`.
- **Columns:** 1-based, in Unicode code points (not UTF-16). SARIF must declare
  `columnKind: unicodeCodePoints` (Phase 5).
- **Decoding:** files are read as UTF-8 with `surrogateescape`; reporters must sanitise lone
  surrogates before printing (Phase 5).
- **Rule crashes:** recorded in `ScanResult.errors` and treated as a failed scan by the CLI
  (exit 2) rather than silently dropped.
- **Config unknown keys:** an unknown key in `.ghostrules.toml` is an error (catches typos).
- **Config from the scanned repo:** honoured as the spec says, but `ScanResult.config_source` is
  kept so the summary can show that a repo-supplied config (which could disable rules or add
  `allow_domains`) was loaded.
- **JSONC:** comment/trailing-comma stripping is string-aware and preserves offsets and lines.

## Applied (Phase 2)

- **Pattern tables pulled forward:** GR005 must know whether a comment "matches any GR010-GR016
  pattern", so `rules/patterns.py` (regex tables, `match_injection`, `find_encoded_payloads`) was
  written in Phase 2. Phase 3 builds the rules on top of it and refines the tables.
- **GR001 flag exception:** only a real subdivision flag (`🏴` + tags spelling `[a-z]{2}[a-z0-9]{1,3}`
  + cancel tag) is ignored. A looser check would let a payload hide behind a flag.
- **GR002/GR003 grouping:** one finding per line (first to last offending character) rather than
  per character. GR001/GR004 are one finding per contiguous run, as specified.
- **GR002 "substantial RTL":** at least 10 Hebrew/Arabic-family letters and at least 30% of all
  letters in the file.
- **GR003 exceptions:** a ZWJ/ZWNJ is only ignored when it is isolated (not part of a run) and
  has a legitimate neighbour: emoji on both sides for ZWJ, or an Arabic/Indic letter on either
  side for ZWJ/ZWNJ. A leading BOM (offset 0) is ignored.
  Severity is high if the line has >= 5 or the file has >= 20 flagged characters.
- **GR004 base exemption dropped:** RULES.md exempts runs "directly following an emoji / CJK base"
  but also sets a threshold of 3. Legitimate use is one selector after one base, so with a
  threshold of 3 the exemption has nothing to exempt, and emoji is the very carrier used by the
  known technique. Runs of >= 3 are always reported.
- **GR005:** comments inside fenced code blocks are ignored (they are visible when rendered);
  an unterminated `<!--` counts as a comment to the end of the file (GitHub hides the rest);
  a GR015 match requires the base64/hex to decode to printable text. GR005 applies to
  `instructions` files and to `other` files with a Markdown extension, never to `config`.
- **GR006:** plain words are checked in `instructions` files only; URLs are checked in every
  kind. Words need Latin letters plus a known lookalike (hand-written table of Cyrillic/Greek
  confusables, defined by code point); URL host labels mixing Latin with *any* Cyrillic/Greek
  letter are flagged. Findings inside a URL are high, plain words low.
- **Columns:** `end_column` is exclusive; multi-line matches are clamped to the end of the first
  line.
- **Fixtures:** generated into `tests/fixtures/unicode/<case>/` by `scripts/make_fixtures.py`,
  committed for reviewability, and regenerated by a session fixture before tests run. The script
  and the tests write invisible and non-Latin characters as escapes only.

## Applied (Phase 3)

- **Matching:** each rule matches the raw text and a whitespace-normalised copy of the whole
  file (`ScanTarget.normalized`, with an offset map back to the original), then drops overlapping
  duplicates. Gaps in GR012 patterns are bounded (200 chars) so the normalised pass cannot join
  distant lines.
- **Scope:** GR010-GR016 apply to `instructions` only (RULES.md: "content of instruction files")
  and have `scans_decoded=True`, so hidden text from GR001/GR004/GR015 is re-scanned by all of
  them (GR015 included, which catches double encoding).
- **GR012 severity:** always critical. The "high elsewhere" case in RULES.md is realised by
  GR105/GR107 (Phase 4), which reuse these patterns for MCP commands and hooks.
- **`allow_domains`:** the scanner hands the list to rules through `ScanTarget.allow_domains`
  (read-only input, rules stay pure). GR012 and GR013 skip a match when every URL in it is on an
  allowed domain; GR013 also skips an allowed collector domain.
- **GR013:** exfiltration forms are critical; a collector domain alone is high, and critical when
  on the same line as an exfiltration instruction. A collector domain inside an already
  reported instruction is not reported again. Known false-positive risk (as specified): "include
  the token ... https://..." fires; use `allow_domains` or an inline ignore.
- **GR014:** `.env` must not be preceded by a word character (so `process.env` is fine) nor be
  `.env.example/.sample/.template/.dist`. A verb negated within three words before it ("never
  print", "do not send") is ignored. For `copy`/`paste`, a path after "to/into/as" is a
  destination, not something read ("Copy .env.example to .env.local").
- **GR015:** high when the run decodes to printable text (shown in `decoded`); medium for opaque
  runs only if they look like random bytes (entropy >= 4.5 bits/char, mixed case and digits, not
  inside a path/URL) and hex runs that are not sha384/sha512 digest lengths. Fenced blocks are
  skipped unless labelled with a shell language; unlabelled blocks count as non-shell.
- **GR010 in code blocks:** low, message "appears inside a code block"; no other rule downgrades.
- **Excerpts:** messages quote the matched text (whitespace collapsed, 80 chars). Secret masking
  of snippets/messages is still to do centrally in Phase 4.

## Applied (Phase 4)

- **Masking (`secrets.py`):** a secret of >= 20 characters is shown as first 4 + `****…` + last 4
  (`ghp_****…a1b2`, the CLAUDE.md format; RULES.md's wording differs only by the ellipsis);
  shorter ones as `****`. `mask_secrets` covers known token formats, bearer tokens, URL
  passwords, and `key=value` / `--flag value` pairs whose name looks secret and whose value looks
  like one (>= 16 chars, entropy >= 3.5, no spaces, not a placeholder/URL/path). It is idempotent.
- **Single choke point:** `Finding.__post_init__` masks `title`, `message`, `snippet`, `decoded`
  and `fix_hint`, so any finding, from any rule, is safe to print, serialise or repr. On top of
  that `build_finding` masks the *line* before cutting the snippet (positions are remapped), so a
  context window can never leave a readable fragment of a secret. Scanner warnings and rule-crash
  errors are masked too.
- **Masking is broader than detection:** a secret glued to letters (`xghp_...`) is still masked
  even though GR101 requires a word boundary to *report* one; the ambiguous `sk-` prefix needs a
  digit and some entropy in that case so words like `task-management-...` are left alone.
- **Reporter guarantee:** reporters do not exist yet. They can only print what `Finding` and
  `ScanResult` hold, which is already masked; `tests/test_secret_masking.py` additionally runs
  every module of `ghostrules.reporters` exposing `render(result) -> str` against a scenario
  with every secret format in every place (Phase 5 reporters must expose that function).
- **Mutation check:** with masking switched off the dedicated tests fail (7 of 9), so they do
  detect a leak.
- **Test secrets:** defanged fakes in `tests/secret_samples.py` with the real shapes; the GitHub
  one is `ghp_` + 36 chars (`EXAMPLE` x5 + `0`), since the spec's 32-char sample cannot match
  GR101.
- **`ServerDef`:** carries `spans` (character offsets of the server key and of each command, arg,
  env value, header value and URL) instead of the single `line` in PLAN §4, so findings point at
  the exact value. Shapes read: `mcpServers`, `servers`, `mcp.servers`, `projects.*.mcpServers`
  (`~/.claude.json`) and Codex `[mcp_servers.*]` (TOML locations are found by text search inside
  the server's table, so they are approximate when the same value repeats).
- **GR101 scope:** known formats are checked in every value of a server (env, args, headers, URL
  incl. query and password) and in the settings `env`; the generic rule needs a secret-looking
  key name (env/header name, `--flag=value`, or the flag before the value, URL parameter).
- **GR102:** knows npx, bunx, `pnpm dlx`, `yarn dlx`, uvx, `pipx run` (value-taking flags
  skipped, `-p/--package/--from/--spec` read as the package). Pinned = exact `x.y.z` (npm) or
  `==`/`@version` (Python) or a git commit SHA; local paths and archive URLs are not judged.
  `pkg@1`, `@latest`, ranges and branch/tag refs are unpinned.
- **GR103:** `http://` only (not `ws://`); `${VAR}` hosts are skipped; loopback = `localhost`,
  127.0.0.0/8, `::1`.
- **GR104:** "filesystem-like" = `filesystem` in the name/package, or a `fs`/`files` token
  (so `pdfsearch` is not one). The package argument itself is never counted as a path.
- **GR105:** also matches `dash/ksh/fish`, combined flags like `-lc`, and PowerShell
  `-enc/-EncodedCommand`; critical when the command string matches a GR012 pattern (which
  includes encoded PowerShell).
- **GR106:** one finding per dangerous option, pointing at that argument.
- **GR107:** besides the specified keys, hook commands are also checked for shell-style
  exfiltration (`curl ... .env`, `cat ~/.ssh/id_rsa | curl`, `env | curl`) and collector domains,
  since GR013's prose patterns would miss them. Gemini `yolo` is read only under `.gemini/`.
- **GR108:** `enableAllProjectMcpServers: true`, plus Gemini-style `"trust": true` on a server
  as the "equivalent auto-trust flag".

## Applied (Phase 5)

- **Default command:** `ghostrules`, `ghostrules .` and `ghostrules --format json` all run `scan`
  (a custom Typer group prepends it unless the first argument is a command or `--help`).
- **Precedence:** CLI flag > config file > default. `--disable` is added to the config's list.
  Config is looked up in the first scan path (or its directory).
- **`--fail-on` scope:** only findings left after `--min-severity` and after inline suppressions
  count, so a hidden finding can never fail the build (and the notes line shows suppressions).
- **Exit codes:** 2 also when the scan itself failed (missing path, crashed rule), even if
  nothing was found, so a broken scan can never look clean. The table then says "Scan
  incomplete" instead of showing a green tick.
- **Output channels:** the table (and its notes, warnings and errors) goes to stdout. For
  `json`/`sarif`/`markdown`, stdout carries only the report and diagnostics go to stderr, so
  `ghostrules scan --format json | jq` always works. `-o FILE` writes the report (table: plain
  text, no colour) and prints "report written to FILE" on stderr.
- **Reporters** each expose `render(result, **options) -> str`; `reporters/common.py` holds the
  shared helpers (it has no `render`, so it is not treated as a reporter).
  Lone surrogates from undecodable input bytes are replaced before output, so nothing can crash
  on encoding, and stdout is switched to UTF-8 when the terminal's code page is not.
- **Table:** findings grouped by file; files ordered by worst severity, then those hiding
  decoded text, then path. Severity badges are colour-coded pills; invisible-character tokens
  are highlighted; the decoded hidden text sits in a red panel titled "Decoded hidden text"
  (no colon: it is a panel title, not a line) with matching malicious phrases and URLs
  highlighted. A finding derived from hidden text already shown above is rendered compactly
  (`↳ ...`) instead of repeating the panel. Snippets stay on one line (ellipsis). Width is
  capped at 120 columns.
- **Ordering of `result.findings`:** severity, then findings that carry decoded hidden text,
  then path/line/column/rule, so every format leads with the hidden instruction.
- **Notes shown to the reader:** configuration loaded from the scanned repo and the number of
  findings hidden by `ghostrules-ignore`, because both can hide findings (see Phase 1).
- **SARIF:** validated in tests against the official 2.1.0 schema (vendored in `tests/data/`,
  checked with `jsonschema`, now a dev dependency). `columnKind` is `unicodeCodePoints`.
  `helpUri` points to `PROJECT_URL#<rule id>`; **`PROJECT_URL` in `ghostrules/__init__.py` still
  has the placeholder `OWNER` and must be set before publishing.** Findings in `--home` files
  are left out and mentioned in the run's notifications.
- **JSON:** the specified keys plus `warnings`, `errors` and, in `summary`, `suppressed`,
  `files_with_findings` and `config_source`.
- **Markdown:** truncated at 100 rows; every cell is escaped (`|`, backticks, `<`, `>`) so
  scanned content cannot inject Markdown or HTML into a PR comment.
- **`reveal`:** numbered listing; tag characters and variation selectors are tokens without
  names (long runs), other invisible characters have names; HTML comments are highlighted;
  decoded ASCII (tags) and bytes (variation selectors) follow each line. Output is masked.
- **`clean`:** removes exactly what GR001-GR004 flag (see Phase 2 exceptions), except
  bidirectional controls in substantially right-to-left files, which are kept and reported.
  A leading BOM goes unless `--keep-bom`. It refuses to overwrite an existing
  `FILE.ghostrules.bak`. Line endings and undecodable bytes are preserved. The dry-run diff
  shows removed characters as tokens and is masked.
- **Demo repositories:** `scripts/make_demo.py` generates `examples/poisoned-repo` (minimal for
  now; Phase 6 completes it so every rule fires) and `examples/clean-repo`; a test checks that
  the checked-in files equal the generator's output.

## Applied (Phase 6)

- **Poisoned demo covers every rule** (RULES.md acceptance criterion), not only the list in
  PLAN §6; a test fails if a newly added rule is not triggered by it. Extra cases beyond the
  plan: `.github/copilot-instructions.md` (variation-selector bytes, base64 payload, Cyrillic
  homoglyphs in a word and a URL, `--dangerously-skip-permissions`), a filesystem server on `/`,
  a `bash -c "curl ... | bash"` server, and `~/.ssh/id_rsa` in the skill. All payloads are
  defanged and generated by `scripts/make_demo.py` from escapes.
- **Hero first, in every format:** findings (and, in the table, files) are ordered by
  severity, then those carrying decoded hidden text, then files nearer the repository root, then
  path. Without the depth rule a nested `.github/...` file sorted before `AGENTS.md` and the
  JSON/SARIF/Markdown reports led with the wrong finding.
- **The GIF:** `demo/demo.tape` (vhs): `cat` the innocent-looking `AGENTS.md`, then
  `scan ... | head -24` (the first 24 lines are exactly the hidden-text block and its derived
  findings; colours are kept with `FORCE_COLOR=1`), then `reveal`. A test estimates the length
  from the tape (typing time plus sleeps, about 12.6 s) and checks the 24-line cut does not split
  the panel. **The GIF itself is not committed**: vhs, ffmpeg and ttyd were not available where
  this was built; run `vhs demo/demo.tape` from the repository root.
- **`.gitattributes`:** `examples/**` and `tests/fixtures/**` are `-text`, everything else LF, so
  Windows checkouts (autocrlf) keep these byte-exact files intact; the "examples are up to date"
  test would otherwise fail on the Windows CI runner.

## Planned for later phases

- **`clean`:** removes only characters the rules actually flag (so emoji ZWJ, flag tag sequences,
  VS16 and legitimate RTL marks survive). A leading BOM is stripped unless `--keep-bom`.
- **Code-block downgrade:** only GR010 drops to `low` inside fenced code blocks (RULES).
- **Self-scan (Phase 9):** exclude `examples/**` as well as test fixtures.
