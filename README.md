# ghostrules

*Find the instructions your AI agent sees but you don't.*

`ghostrules` scans a repository (and optionally your machine) for hidden instructions and risky
configuration in the files AI coding agents read and obey: `AGENTS.md`, `CLAUDE.md`,
`.cursorrules`, Copilot instructions, skills, MCP configs and more.

It is a defensive tool: it only reads files and reports findings. It never executes anything it
finds and never makes network requests.

> Work in progress (pre-0.1.0). The full README lands in the final phase.

## Usage

```bash
pip install -e ".[dev]"                    # from a checkout, for now

ghostrules scan .                          # scan the current repo (`scan` is the default command)
ghostrules scan examples/poisoned-repo     # a defanged demo that must find issues
ghostrules scan --home                     # also your user-level agent configs (read-only)
ghostrules reveal AGENTS.md                # show invisible characters and the text they hide
ghostrules clean AGENTS.md                 # dry run: diff of what would be removed
ghostrules clean AGENTS.md --write         # remove it (keeps AGENTS.md.ghostrules.bak)
ghostrules rules                           # list every rule
```

| `scan` option | Default | Meaning |
|---|---|---|
| `PATH ...` | `.` | Files or directories to scan |
| `--format` | `table` | `table`, `json`, `sarif` or `markdown` |
| `-o, --output FILE` | stdout | Write the report to a file |
| `--fail-on` | `high` | Exit 1 if a finding is at least this severe (`none` to never fail) |
| `--min-severity` | `low` | Hide findings below this severity |
| `--all-files` | off | Check every text file for hidden Unicode, not just agent files |
| `--home` | off | Also scan user-level agent configs |
| `--disable GR010,GR012` | | Disable rules |
| `--config FILE` | auto | Config file (default: `.ghostrules.toml` in the scan root) |
| `--no-color` | off | Plain output |

Exit codes: `0` nothing at or above `--fail-on`, `1` findings at or above it, `2` usage or
runtime error (including a rule that crashed or a path that does not exist).

### Try it on the demos

```bash
ghostrules scan examples/poisoned-repo     # finds 28 issues across 7 files, exit code 1
ghostrules reveal examples/poisoned-repo/AGENTS.md
ghostrules scan examples/clean-repo        # "No findings", exit code 0
```

`examples/poisoned-repo` looks like a small ordinary project but hides defanged malicious
instructions in invisible Unicode, an HTML comment, MCP configs and agent settings: every
rule fires at least once. `examples/clean-repo` is a realistic setup that must stay clean.
Both are generated by `scripts/make_demo.py` (the invisible characters are reproducible).

Secrets are never printed: tokens are shown masked, as in `ghp_****…a1b2`, in every format.

## GitHub Action

Copy this into `.github/workflows/ghostrules.yml`. Findings appear in the job summary and, with
`upload-sarif`, in the repository's **Security → Code scanning** tab.

```yaml
name: ghostrules
on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: read
  security-events: write # needed to upload the SARIF report

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: OWNER/ghostrules@v0   # replace OWNER once the repository is published
        with:
          fail-on: high        # critical | high | medium | low | info | none
          all-files: "false"   # also check every text file for hidden Unicode
          upload-sarif: "true" # set to "false" where code scanning is unavailable
```

| Input | Default | Meaning |
|---|---|---|
| `path` | `.` | What to scan. Keep `.`: SARIF locations are relative to it |
| `fail-on` | `high` | Fail the job at this severity or above (`none` never fails) |
| `all-files` | `false` | Also check every text file for hidden Unicode |
| `upload-sarif` | `true` | Upload to code scanning (needs `security-events: write`) |

The report is always written to `ghostrules.sarif` and summarised; the job is failed only at the
end, so the upload happens even when the scan finds problems. The upload cannot fail the job
(it is not available on forks or on private repositories without code scanning).

## pre-commit

```yaml
repos:
  - repo: https://github.com/OWNER/ghostrules   # replace OWNER once the repository is published
    rev: v0.1.0
    hooks:
      - id: ghostrules
```

The hook runs `ghostrules scan` on the whole repository (it needs no file list) and blocks the
commit when something at or above `high` is found.
