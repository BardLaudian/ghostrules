# Contributing to ghostrules

Thanks for helping. A noisy scanner gets uninstalled, so **precision matters as much as
coverage**: every change to a detection comes with a positive and a negative test.

## Set up

```bash
git clone https://github.com/BardLaudian/ghostrules && cd ghostrules
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

pytest -q                         # tests
ruff check . && ruff format .     # lint and format
mypy src                          # types (lenient is fine)
ghostrules scan examples/poisoned-repo   # must find issues, exit code 1
ghostrules scan examples/clean-repo      # must report nothing, exit code 0
```

The documents in `docs/` are the contract: `RULES.md` (every rule), `AGENT_MODELS.md` (how each
agent loads its instructions, with sources) and `DECISIONS.md` (choices made where they were
ambiguous). `docs/design/` is the **design history**: the original `SPEC.md` and `PLAN.md` and the
per-version design documents (`v0.1.1/`, `v0.2/`). They explain why things are the way they are and
are not kept up to date. If code and the contract documents disagree, fix one of them in the same
pull request.

## Add a rule in three steps

1. **Write the rule.** Add a function to the module that fits (`src/ghostrules/rules/unicode.py`,
   `injection.py`, `mcp.py` or `agent_settings.py`) and register it with the decorator:

   ```python
   @rule(
       "GR017",                       # next free id: GR0xx = instruction files, GR1xx = config
       Severity.HIGH,                 # typical severity
       "Short title",
       "One sentence on what it finds and why it matters.",
       ("instructions",),             # file kinds it applies to
       scans_decoded=True,            # also run on hidden text decoded by other rules?
   )
   def gr017_something(target: ScanTarget) -> Iterator[Finding]:
       ...
       yield build_finding(target=target, rule_id="GR017", ...)
   ```

   Rules are **pure**: they receive a `ScanTarget` and yield `Finding`s, with no I/O and no global
   state. Use `build_finding` so line, column, snippet and secret masking come out right. Put
   shared regular expressions in `rules/patterns.py`.

2. **Test it.** Add at least one positive and one negative test (see `tests/test_rules_*.py`). Add
   a case to `scripts/make_demo.py` so `examples/poisoned-repo` triggers the rule (a test fails
   if a `GR00x`, `GR01x` or `GR1xx` rule does not fire there; the import rules `GR02x` are tested
   in `tests/test_scan_imports.py`) and make sure `examples/clean-repo` still reports nothing.
   Fixtures with invisible characters are generated by `scripts/make_fixtures.py`.

3. **Document it.** Describe the rule in `docs/RULES.md` (ID, severity, logic, true and false
   positive examples), note any judgement call in `docs/DECISIONS.md`, add a line to
   `CHANGELOG.md`, then refresh the rule index in `docs/RULES.md`:

   ```bash
   python scripts/make_demo.py
   python scripts/gen_rules_table.py --write
   ```

## Add an agent model

`ghostrules context` and `ghostrules lock` need to know how an agent loads its instructions. A
model is one module, one section of `docs/AGENT_MODELS.md` and its tests:

1. **Write down what the agent's documentation says** in a new section of `docs/AGENT_MODELS.md`:
   which files it reads and in what order, which are conditional or loaded on demand, whether it
   follows `@` imports (relative to what, how deep), what it strips before the model sees the text,
   and the page and date you checked. Anything the documentation does not state is marked
   **UNVERIFIED** and modelled conservatively (a file the agent might read is included). Model only
   what is written there.
2. **Implement it** in `src/ghostrules/agents/<name>.py` with a `build(repo, *, cwd, target, home)`
   method that returns a `ContextGraph`. Use the `Builder` in `agents/base.py`: it reads files
   safely (never through a symlink), applies your text transforms (`render_*`), follows imports
   with the `ImportPolicy` you pass, hashes the result and records the edges. Register the model in
   `agents/__init__.py` (`AGENT_NAMES`, `get_model`) and in `config.AGENT_NAMES`. Use
   `globs.matches_any` for `paths`/`globs`/`applyTo` and `markdown_utils.parse_frontmatter` for
   front matter.
3. **Test it with a fake repository** built in `tmp_path` (see `tests/test_agents_claude.py`):
   given the tree, the working directory and the target, the ordered entries, their `load`
   states, `matches` and `unverified` flags must be what the documentation implies. Add the
   precedence and depth cases that apply to the agent.
4. **Say what you could not model** (user-level or organisation settings, environment variables)
   in `ContextGraph.notes`, and add a line to `CHANGELOG.md` and a decision to
   `docs/DECISIONS.md` for every judgement call.

## Rules of the repository

- **Defanged only.** Fixtures, demos and tests use `attacker.example`, `exfil.example`,
  `example.com` and obviously fake tokens such as `ghp_` + `EXAMPLE` repeated. Never real
  domains, real webhooks or working payloads.
- **Invisible characters are generated, never typed.** Write them as escapes or with `chr()` in
  the generators. A test fails if a literal invisible character ends up in the sources.
- **Never execute, download or evaluate scanned content**, and no network libraries at runtime.
- **Secrets are always masked.** Anything that prints text from a scanned file goes through
  `ghostrules.secrets.mask_secrets` (findings do it for you).
- Type hints everywhere, small functions, docstrings on public functions, English README.
- Conventional commits (`feat:`, `fix:`, `test:`, `docs:`...).

## Pull request checklist

- [ ] `pytest -q`, `ruff check .`, `ruff format --check .` and `mypy src` pass
- [ ] positive and negative tests for every new or changed detection
- [ ] `examples/poisoned-repo` still triggers every rule; `examples/clean-repo` is still clean
- [ ] `docs/RULES.md`, `docs/DECISIONS.md`, `CHANGELOG.md` and the README table are updated
- [ ] for an agent model: `docs/AGENT_MODELS.md` cites the documentation and the date, and the
      unverified parts are marked
- [ ] nothing real in the fixtures: no secrets, domains or payloads that work
